# Candidate-resolution IRV calibration protocol

**Preregistered:** 29 October 2026  
**Status:** historical architecture calibration only; no canonical 2026 forecast change  
**Predecessor:** PR #138 / `IRV_FINAL_PAIR_CALIBRATION_RESULTS_2026-10-28.md`

## 1. Question

PR #138 found that the current five-family Assembly IRV mechanism is directionally useful but increasingly overconfident about final pairs, and that 12 of its 16 wrong modal historical final pairs place the collapsed `OTH_IND` family in the modal pair when the observed final pair contains no `OTH_IND`.

The first new question is deliberately narrower than a general preference-model refit:

> Does resolving the heterogeneous `OTH_IND` pool into the actual minor-party and independent candidates materially improve historical elimination/final-pair calibration while leaving the existing cross-family preference mean structure otherwise intact?

This workstream tests architecture before tuning preference means. It must not use 2026 seat outputs, October 2026 seat polling, analyst seat calls, or desired 2026 final pairs to select a model.

## 2. Frozen comparator

`R0` is the existing C0 historical benchmark from PR #138:

- five collapsed model families: `ALP`, `LIB_NAT`, `ONP`, `GRN`, `OTH_IND`;
- the current production `PREFERENCE_PRIOR` mean structure;
- Dirichlet concentration 72;
- one family preference draw shared across districts in each simulated election;
- deterministic lowest-tally IRV elimination;
- observed historical five-family first preferences as the starting vote vector.

The existing C0 results are not reinterpreted or refitted in this PR.

## 3. R1 architecture

`R1` changes only the representation of `OTH_IND`.

For each historical district:

- every actual `Other/Independent` candidate in the governed VEC candidate-primary file remains a separate IRV contender with their observed first-preference share;
- `ALP`, `LIB_NAT`, `ONP` and `GRN` remain one aggregate contender each, exactly as in R0;
- the sum of the R1 starting vote vector must reconcile to the same district formal vote and the same five-family totals used by R0;
- no candidate is created, merged, deleted or reclassified from information outside the governed candidate-primary files.

This is intentionally not a full candidate-level model. Keeping the four named families collapsed isolates the specific architecture failure diagnosed in PR #138 rather than simultaneously changing Coalition three-corner contests, major-party candidate identity, One Nation candidate structure and preference means.

## 4. Transfer mechanics

### 4.1 Existing cross-family mean structure is retained

For transfers between model families, R1 retains the current `PREFERENCE_PRIOR` mean structure. The four named-family rows are sampled with concentration 72 exactly as in C0.

When a named-family row assigns mass to `OTH_IND`, that mass must be allocated among the *currently continuing* OTH/Independent candidates:

- **primary rule:** equal allocation among continuing OTH/Independent candidates;
- **declared sensitivity only:** allocation proportional to those candidates' current tallies.

The sensitivity is not an alternative model to be selected after scoring. If the scientific conclusion changes between the two allocation rules, candidate resolution is adjudicated as unresolved.

### 4.2 Operational OTH-to-OTH retention

Once OTH/Independent candidates are separate, an eliminated OTH candidate can transfer to another OTH candidate. The five-family C0 matrix cannot represent this because within-family transfer is collapsed away.

R1 therefore introduces one operational quantity, `q_oth`:

> the effective share of an eliminated OTH/Independent candidate's parcel transferred to continuing OTH/Independent candidates, conditional on at least one such candidate remaining.

`q_oth` is **not** labelled an original voter-preference rate. Later VEC exclusion parcels can contain previously transferred ballots. It is an operational elimination-stage parameter only.

For an eliminated OTH candidate:

1. allocate `q_oth` across continuing OTH candidates using the frozen allocation rule;
2. allocate `1 - q_oth` across continuing named families using the current OTH row's cross-family proportions (`ALP`, `LIB_NAT`, `ONP`, `GRN` = 0.30, 0.26, 0.31, 0.13), with their C0 concentration-72 uncertainty retained;
3. if no OTH candidate remains, renormalise all mass across continuing named families;
4. if one or more named families have already been eliminated, renormalise the cross-family component over the named families still continuing.

No new cross-family OTH mean is fitted in R1.

## 5. Historical evidence for `q_oth`

Use only the official-VEC effective exclusion-parcel audit generated by `audit_historical_assembly_effective_transfer_events.py`.

Eligible events satisfy all of:

- `source_family == OTH_IND`;
- at least one *other* OTH/Independent candidate is continuing, operationalised by `destination_candidate_count[OTH_IND] >= 1`;
- `parcel_votes > 0`;
- the distribution row reconciles under the existing audit checks.

For each eligible event define:

`event_retention = within_source_family_votes / parcel_votes`.

To avoid falsely treating thousands of ballots in one mixed parcel as independent observations:

- first average eligible event retention within each district-election;
- the district-election mean, not the ballot, is the calibration unit;
- estimate uncertainty by block bootstrap over district-election units;
- use 5,000 bootstrap draws with seed `20261029`;
- each bootstrap draw is the unweighted mean of sampled district-election means.

No ballot-weighted Beta/binomial pseudo-sample is permitted.

### Identification gate

A target-cycle R1 score may use an empirical `q_oth` distribution only if the earlier-cycle training set contains:

- at least **20 eligible OTH exclusion events**;
- at least **10 district-election units**.

If the gate fails, R1 for that target cycle is **not scored**. The threshold is not lowered after evidence counts are inspected.

## 6. Walk-forward chronology

Only prior elections can calibrate a target election:

- 2014 target: train `q_oth` on 2010;
- 2018 target: train on 2010 + 2014;
- 2022 target: train on 2010 + 2014 + 2018.

2022 cannot inform the 2022 R1 parameter. No 2026 evidence participates in historical fitting or scoring.

The 2010 cycle remains useful as training evidence but is not an R1 target because there is no earlier Victorian cycle in the governed evidence set from which to estimate `q_oth` under this protocol.

## 7. Simulation coupling

For each target cycle:

- 5,000 simulations;
- election seed `20261028`, matching the C0 historical benchmark convention;
- one family-level preference draw per simulated election shared across all districts, as in C0;
- one bootstrap `q_oth` draw per simulated election shared across all districts in that target cycle;
- the same `q_oth` draw is used for the primary equal-allocation run and the proportional-allocation sensitivity so their difference isolates allocation rule rather than parameter randomness.

Where practical, C0 and R1 should use common family-preference random numbers.

## 8. Outcome scoring

Historical outcome files are scoring-only. They are not read by the fitting stage.

Primary comparison is on the exact same genuine-IRV final-pair universe used by PR #138, expressed at model-family level so R0 and R1 are directly comparable.

Report for each target cycle and pooled 2014/2018/2022:

- winner modal accuracy;
- winner mean Brier score;
- winner mean log loss;
- final-pair modal accuracy;
- final-pair mean Brier score;
- final-pair mean log loss;
- number of observed final pairs assigned zero probability in 5,000 draws;
- number of wrong modal pairs containing an OTH/Independent contender when the observed pair contains no OTH/Independent family.

Secondary R1 diagnostics:

- exact OTH/Independent candidate identity when an OTH candidate reaches the simulated final pair;
- number of districts in which multiple OTH candidates are initially present;
- number of elimination paths in which an OTH-to-OTH transfer occurs;
- equal-allocation versus proportional-allocation sensitivity.

## 9. Frozen adjudication rule

R1 is historically **supported** only if all of the following hold on the pooled 2014/2018/2022 genuine-final-pair universe:

1. final-pair mean log loss improves by at least **0.05** versus the matched R0/C0 benchmark;
2. final-pair mean Brier score does not worsen;
3. winner mean Brier score worsens by no more than **0.02 absolute**;
4. the number of phantom OTH/Independent modal final-pair errors falls;
5. the direction of conclusions is the same under equal and proportional OTH-destination allocation.

These thresholds are architecture-screening rules, not a production-promotion gate.

If R1 fails, do not tune `q_oth`, change the allocation rule or widen preference uncertainty in response to the failed score inside this experiment.

If R1 passes, the next workstream may separately preregister preference-uncertainty calibration. R1 passing does **not** authorise changing concentration 72 or the production forecast.

## 10. Prohibited leakage / post-hoc actions

Before historical R1 results are generated, this protocol forbids:

- inspecting 2026 Assembly R1 outputs;
- using Roy Morgan October seat polling or analyst seat calls to fit or choose R1;
- fitting new cross-family preference means;
- choosing between equal and proportional OTH allocation based on historical score;
- reducing the evidence gate;
- selecting a `q_oth` point estimate from a target election;
- promoting R1 into PROD.

Any protocol defect found before scoring must be documented as an amendment committed before rerunning the score.

## 11. Production boundary

This branch is validation infrastructure only. Canonical polling inputs, geography, forecast parameters, forecast outputs and production-authorisation state remain unchanged.
